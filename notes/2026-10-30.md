## 做了什么

- **主线**：栈和队列的唯一区别是「从哪一头出」。
  - 栈 LIFO：同一头进出 → `list.append` / `list.pop` / `list[-1]`，全在**右端**，O(1)
  - 队列 FIFO：一头进一头出 → `deque.append` / `deque.popleft`，O(1)
  - 循环队列：`(i + 1) % capacity` 绕回复用空间（概念级，未手写）
- **`src/day08_stack_queue.py`**：
  - `Stack`（list）：`push` / `pop` / `peek` / `is_empty` / `__len__`
  - `Queue`（deque）：`enqueue` / `dequeue` / `is_empty` / `__len__`
  - 5 组断言：空结构 / 单元素 / 多元素（含 a-b-c 交错进出）/ 空的时候必须抛 IndexError / 两实例不串味

## 卡点（3 个）

1. **push 用 `insert(0, value)` —— 栈顶方向与 pop 端不一致**
   `insert(0)` 把新元素放左端，`pop()` 却从右端取 → 弹出顺序变成 `1,2,3`（FIFO），
   第 3 组断言会抓（应得 3 拿到 1）。
   **规则：栈只有一个头。** 栈顶定在左端，`pop` / `peek` 就必须一起放左端；定在右端就全在右端。
   只改一个，结构就变味。
   另外 `insert(0)` 本身是 **O(n)**（插入点后面全体右移），栈的 push 本该 O(1) —— 顺手把优势也丢了。

2. **`self._data.pop()` 少了 `return`**（今天最隐蔽的一个）
   元素确实弹出去了，但函数返回 `None`，`assert s.pop() == 1` 失败。
   这类 bug **不报错、不崩，结果静默错** —— 只 print「成功」看不出来，只有断言能拦。

3. **`is_empty` 判 `self._data is None`**
   `_data` 在 `__init__` 里就是容器，**永远不可能是 None**；而且没有 `return True` 的分支 →
   隐式返回 `None` → `assert ... is True` 失败。
   **空容器的判断是 `not data`**（空 list / dict / str 本身为假），不是 `is None`。
   `is None` 问的是「对象还没建」，不是「容器里没东西」—— 两件事。

## 概念收获

- **`self._data(len(self._data)-1)` 与 `self._data[-1]`**：前者圆括号 = 调用，
  list 不可调用 → `TypeError: 'list' object is not callable`；后者方括号 = 取值。
  负索引 `[-1]` 直接指最后一个，不用 `len-1` 手算。
- **空的时候抛异常，不返回 None**：`return None` 让调用方分不清「弹出来就是 None」和「栈空了」，
  错误会静默往下传。`list.pop()` / `deque.popleft()` 空表时本来就抛 `IndexError`，
  **不需要自己写 if** —— 少写一个分支，还白得一个正确的错误类型。
- **`popleft` vs `pop`**：deque 的 `pop` 拿右端（= 栈顶），`popleft` 拿左端（= 队头）。
  队列写成 `pop()` 就变成栈，第 3 组断言当场抓。
- **断言要用 `is True` / `is False`**：`assert s.is_empty()` 放行 `None`、`0`、`""`；
  `assert s.is_empty() is True` 只认严格的 `True` —— 今天正是它抓住 `is_empty` 返回 `None`。
- **压测要「对拍」不要「重跑自己的断言」**：随机 500 组 + 用「倒序 / 原序」这个与实现无关的
  参考结果做裁判，才叫独立验证。自己重跑自己的断言只是把同一个假设再念一遍。
