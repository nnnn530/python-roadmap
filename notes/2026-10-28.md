   （10.22 漏 `cd` 在家目录误建仓库，是同一个毛病换了个马甲。）

2. **`import argparse` / `import sys` 不知道是什么**
   以为是「功能」，其实是「去工具箱拿工具」。不 import 就是 `NameError`。
   - `argparse`：Python 自带的参数解析器（`D:\Python\Lib\argparse.py`），
     没有它就得自己从 `sys.argv` 那串原始字符串里一格一格抠。
   - `sys`：跟系统/解释器对话，今天只用了 `sys.exit(0/1)` —— 退出码是给别人脚本判断成败的。
     它没有 .py 文件，内置在解释器里。

3. **VS Code 的运行按钮不带参数**
   点 ▷ 等于裸跑 `python main.py`，argparse 回 `required: --file`。
   **这不是坏了，是程序在正确拦人**。以后带参数的程序一律用终端敲命令。

## 概念收获

- **`import` 是拿工具，不是「启用功能」**：Python 启动只自带一小撮（`print`/`len`/`dict`），
  其余要伸手去拿。`import argparse` = 从 `Lib` 目录把那个 .py 叫醒。
- **`--file` 两种写法**：位置参数（`parser.add_argument("file")`，敲 `python main.py data.txt`）
  和可选参数（`add_argument("--file", required=True)`，敲 `--file data.txt`）。
  验收命令用的是后者，所以改成后者 —— **接口定义跟着使用方式走，不能反过来。**
- **`type=int` 不写，`--top` 拿到的是字符串 `'5'`**：跟 `input()` 一模一样，命令行的东西天生是字。
- **`str` 的 `sys.argv` 是原始材料**：`['--file', 'data\\sample.txt', '--top', '3']`，
  全是字符串。argparse 干的就是把这串脏活理顺。
- **异常该在哪一层变成人话**：`io_utils.read_text` 只管 `raise`，`main.py` 才 `print` + `return 1`。
  分层之后，同一个读文件函数能被 pytest 测、被网页接口调，各自决定怎么报错。
- **退出码是契约**：0 成功、1 自己的错误、2 argparse 拦下的用法错误。
  别人用 `&&` 串流程全靠这个数字。
- **`3 < 5` 的循环必写 `l < r`**：`l <= r` 只多一次「自己跟自己换」，不炸但多余；
  交换次数是 `len // 2`，中间那个元素永远不用动。
- **`s = s[::-1]` 与 `s[:] = s[::-1]` 的分水岭**：前者改名指向新列表，后者往老列表里塞。
  跟 10.27 的「便签不是盒子」是同一件事。
- **`r"""` 前缀**：docstring 里写 `D:\code\...` 会被当成转义序列 `\c`，触发 `SyntaxWarning`。
  路径里带反斜杠的字符串，前缀一律加 `r`。

## 追加：项目加日志 + 分层错误处理（同日，commit `f0e4609`）

原本排在 10.29，今天提前做完。

### 做了什么

- **日志三件套**：`logging.getLogger(__name__)`（每个模块只广播）、`logging.basicConfig(handlers=..., level=..., format=...)`（只在 `main.py` 配置）
- **级别当门槛**：`DEBUG(10) < INFO(20) < WARNING(30) < ERROR(40) < CRITICAL(50)`；
  默认级别设成 `CRITICAL + 1` = 全关，`-v` 才放行到 `DEBUG`；`--log-file` 固定 DEBUG
- **日志格式**：`%(asctime)s %(levelname)-7s %(name)s: %(message)s`，`%(name)s` 打出 `io_utils` / `counter`，一眼看出谁在说话
- **三条路分流**：结果 → stdout；用户能看懂的错 → stderr（`print(..., file=sys.stderr)`）；诊断 → logging
- **错误分类更细**：读侧补 `UnicodeDecodeError` + `OSError` 兜底；写侧补「输出目录不存在」`FileNotFoundError`、被占用 `PermissionError`
- **入口校验**：`--top` 的 `type=` 换成自定义函数 `positive_int`，抛 `ArgumentTypeError` → argparse 自动报错 + 退出码 2
- **双重防御**：`top_n` 内部仍保留 `n <= 0` 检查（库不信任调用方，明天网页接口也会调它）

### 新踩到的点

1. **`except OSError` 必须写在所有子类之后**
   `FileNotFoundError` / `PermissionError` / `IsADirectoryError` 全都是 `OSError` 的子类。
   顺序写反，具体分支永远轮不到，全被兜底那条吞掉 —— 提示变成「读失败：xxx」，等于白分类。
2. **`log.xxx` 用 `%s` 占位，不用 f-string**
   级别挡住时 f-string 已经拼好字符串（白干活），占位符是真正要输出时才格式化。
3. **`basicConfig` 只生效一次**
   第二次调用被静默忽略（pytest 里多文件共享配置时必踩）→ 加 `force=True` 重置。
4. **直接运行某个文件时，`__name__` 是 `"__main__"`**
   所以 `counter.py` 自测的日志前缀显示 `__main__` 而不是 `counter`；
   被 `main.py` import 后才变回模块名。这正是 `if __name__ == "__main__"` 那个判断的另一面。
5. **往不存在的目录写文件抛的是 `FileNotFoundError`**
   同一个异常类，读和写的含义完全不同（读=文件没有，写=文件夹没有），提示文案得分开写。
