## 做了什么

- **主线**：数组 vs 链表 —— 连续内存靠「算地址」按下标 O(1)，链表靠「改指针」头插/删除 O(1)；
  中间插入整体仍是 O(n)，因为**找位置 O(n)、插这个动作才 O(1)**。
- **两种遍历**：尾插/找尾巴 `while node.next is not None`（停在最后一个节点）；
  收集全部 `while node is not None`（走到 None）。**先想「我要停在哪」，条件自然出来。**
- **栈 / 队列**：栈 LIFO（`list.append` / `list.pop`）；队列 FIFO 必须用 `collections.deque`
  （`list.pop(0)` 是 O(n)，后面全体前移）。循环队列只是概念：`(i + 1) % capacity` 绕回。
- **补课 class 语法**（原计划 11.2）：`__init__` 是造对象时自动跑一次，负责贴属性；
  `self` 是「我自己」，定义方法必写、调用时不传（`d.bark()` ≡ `Dog.bark(d)`）；
  `__len__` 这种双下划线方法是「给 Python 看的暗号」，定义了 `len()` 才有得接。
- **`src/day08_class_warmup.py`**：`Dog`（name/count/bark/`__len__`）+ `NumberBox`（head/size/add/reset），
  用和链表同构的小类先把「便签 + 计数器」分开。
- **`src/day08_linked_list.py`**：`Node(value, next)` + `LinkedList`（`append` / `prepend` /
  `delete` / `to_list` / `__len__` / `reverse`），**11 组断言全绿**，含空链表 / 单节点 /
  删头节点 / 删尾节点 / 删不存在的值 / reverse 两次复原。

## 卡点（3 个）

1. **`next` 长在 Node 上，不长在 LinkedList 上**
   把「走路的便签 `node`」和「链表身上的计数器 `self.size`」混了，写出
   `while self.size != None: self.size = self.next`。
   `size` 是数字 `0`，`0 != None` 恒真（死循环）；`self.next` 直接 `AttributeError`。
   正确：`node = self.head` 贴便签，`node = node.next` 一张张挪；`self.size += 1` 只管计数。

2. **`reverse` 从 `self.head` 起步 → 空链表崩 + 成环**
   `cur = self.head.next` 在空链表上是 `None.next` → `AttributeError`；
   而且第一轮 `2.next = 1` 时 `1` 还指着 `2`，链成环，只能靠末尾 `self.head.next = None` 拆环，
   漏拆则 `to_list()` **死循环**（不报错、不退出，比报错难查）。
   改法：`prev = None` / `cur = self.head` 起步 —— 空/单/多一套代码，从根上不成环。

3. **改了没存盘就运行（两次）**
   VS Code 标签页的白点 = 未保存，跑的是磁盘上旧版本，报的还是旧错（`NotImplementedError`）。
   规矩：**Ctrl+S 再跑**；看报错行号/文案是不是新代码的。

## 概念收获

- **「改之前先记住」今天出现三次**：头插要「先接旧链、再改 head」；删除要留 `prev`
  （`prev.next = cur.next`）；反转要留 `nxt = cur.next`。共同点：下一步要覆盖的指针，
  **覆盖前必须先复制到别处**，否则后半条链永久丢失。
- **便签不是盒子（10.27 的延续）**：`node = self.head` 没复制任何节点，
  只是多一张指向同一对象的便签；所以 `node.next = new` 改的是真链表。
- **哨兵 / dummy 的预告**：`delete` 里「删头节点」要特判，是因为头没有前一个。
  若先造 `dummy.next = head` 再让 `prev` 从 dummy 起步，头节点就不用特判 —— **LC21 要用**。
- **`delete` 的 `prev` 要慢一步**：循环里 `prev = prev.next; cur = cur.next`（或 `prev = cur; cur = cur.next`），
  顺序反了 `prev` 会追到 `cur` 身上，删不掉任何东西。
- **占位符 `raise NotImplementedError` 写完实现要删**，否则跑起来还是「还没写」，容易误判。
- **变量名避开 `list` / `next` 等内置名**：`to_list` 里写成 `list = []`，
  函数内之后所有 `list(...)` 全部失效（10.25 `stats(list)` 同源）。
